# 山西扣点点规则差异与实现记录

日期：2026-10-18。对照对象：用户提供的金币场、亲友房规则及随后补充。

本报告记录最初规则升级时的差异。程序沿用 Java 21 / Swing，不迁移到此前规划的 C#。当前为 2.2.1；按用户要求仅保留最新开发源码及发布包。

## 统计口径

将规则拆为下表 58 项可核查行为，每项等权；这不是代码复用比例，也不是工作量百分比。旧版“部分”表示有相关基础实现，但不满足完整语义；“缺失”表示没有对应逻辑；“冲突”表示明确采用了不同规则。

旧版：**符合9项、部分符合6项、明确冲突3项、缺失40项**。即58项中有49项需要修改或补充（含按用户要求留白/取消的项目）；不能将已有通用麻将算法误算为已实现地方结算。

新版按补充处理了3项特殊边界：第45项数值留白、55项跟庄判定留白、51项不启用。其余功能及可配置入口见下表，实测覆盖见验证报告。

## 用户后续明确的口径

1. 胡几点取胡进那张牌的牌面点数；万筒条 1～9，字牌 10。
2. 只隐藏报听动作打出的那张牌；这张牌不可被碰、杠、胡。后续弃牌正常公开。
3. 亲友房牌型翻倍/加点数值先留空，不能擅自填默认数值。界面允许用户明确填入数值后才启用。
4. 风嘴子有独立开关，默认关闭。
5. 跟庄成功的判定留白，因此跟庄功能不启用，也不产生跟庄分。
6. 一家承包支付三家的合计份额。
7. “点炮者包胡家杠”单独选项不启用；原规则另列的“点炮包胡包杠”“未报听点炮包杠”仍为可选项，默认关闭。

## 工程约定与仍需确认的边界

以下内容不是用户已确认的额外规则，已采用明确、可测试的实现口径，后续可调整：

- 报听门槛解释为至少有一个合法听口达到指定点数；报听后锁定全部合法听口（含仅能自摸的3～5点）。报听后普通出牌只能打刚摸到的牌。
- “过圈”按本人下一次正常摸牌或杠后补牌解除过胡限制。若当地要求不同，需调整 `Game.draw`。
- 三张相同牌时直接禁止碰，避免先碰再杠；不是允许碰后永久禁止升级的另一种口径。
- 最后一张摸入牌仍可胡；不能再补牌时不给杠选项。无胡后再次需要摸牌而牌墙为空时荒庄。荒庄留庄。
- 豪华七对含至少一个四张组，金币统一4倍，不擅自增加“双豪华/三豪华”档位。
- 捉双耗子随机选择两个不同牌种，该牌种全部四张均为万能牌；不另造或移除牌张。
- 亲友房普通杠分局末结算，荒庄默认保留已成立杠分；若开“杠随胡走”则荒庄不计杠分。
- 风嘴子从胡家的一种合法分组计算；多个分组取总胡分与风嘴子分较高的一种，禁止把不兼容分组的碰碰胡、风嘴子重复相加。依赖风嘴子成牌的胡牌仅限自摸，不可点炮或抢杠胡；普通成牌拆法接炮时排除风嘴子分组和费用。
- 带庄按庄家与各对手的每笔胡分份额加5/10；承包时汇总这些份额，不额外重复乘倍数。
- 额外“点炮包胡包杠”与“未报听点炮包杠”在界面互斥；若同时选择“杠随胡走”，先过滤可结算杠，再改付款人。
- 新建牌桌会开启新积分场；重新开局会回退本局已入账杠分，以免金币场重复刷分。没有存档和跨进程恢复。

## 代码结构与验证入口

- `Rules.java`：房间配置、互斥验证、牌面值、金币固定倍数。
- `HandRules.java`：普通胡、特殊胡、耗子、风嘴子、牌型分组。
- `Scoring.java`：纯函数付款账本、承包和计分，使用64位整数。
- `Game.java`：状态机、听牌限制、争抢裁决、杠事件、信息隐藏。
- `RulesDialog.java`：房间选项；亲友房牌型数值空白；禁用待定选项。
- `EngineTest.java`：保留原向听算法14,636条对照数据，新增扣点点固定牌例、付款矩阵与完整机器人对局。
- `Smoke.java`：真实Swing窗口、鼠标选牌/出牌、报听按钮、窗口尺寸、结算和下一局测试。
