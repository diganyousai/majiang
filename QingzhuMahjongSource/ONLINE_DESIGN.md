# 四人房间实现边界与协议（2.2.2）

2.2.0 更新共用 Artwork / Board 的牌面与界面样式；保持协议 v1 和现有扣点点规则。素材与引擎编号映射见 ARTWORK.md。

`Game.view()` 只在 `Phase.OVER` 公开四家的手牌、弃牌及暗杠；下一局恢复原有按玩家过滤。`RoundReview` 只接受已结束局的不可变快照，不包含未摸牌墙。传输字段和协议版本不变。

2.2.2 增加本机身份自动恢复座位；听后平时只能打出刚摸的牌或胡，不能碰或换手牌，保持原听口不变时可杠，沿用普通杠计分。原有风嘴子仅自摸及局末全场牌展示保留。四人更新后重新建房。

## 模块

| 模块 | 职责 |
| --- | --- |
| Game / Rules / HandRules / Scoring | 原规则状态机与结算，新增可指定四个真实玩家昵称的构造器 |
| RoomProtocol | 协议v1、256KiB最大帧、显式字段编码、带上限的集合读取；不使用Java对象反序列化 |
| RoomServer | 单房间四座位、认证、串行命令、准备、游戏状态、按玩家视图广播、心跳、断线暂停 |
| RoomClient / PlayerIdentityStore | 连接、心跳、同ID重试；每个本机昵称持久保存192位随机玩家身份，关闭客户端后自动恢复；不依赖Swing |
| MultiplayerWindow | 只管理本人可见快照和界面，不持有主机完整Game或其他玩家手牌 |
| RoomDialogs | 启动菜单、开房、加入、独立主机窗口 |
| Board | 按viewer旋转显示，绝对座位仍由服务器维护 |
| RoomSelfTest / RoomSmoke | 真实回环TCP测试、四个真实图形客户端回归 |

现有代码采用无外部依赖的Java21/Swing。本轮先使用长度前缀TCP与显式二进制DTO，未照搬早期C#/WebSocket/JSON规划。房间协调与客户端均通过RoomProtocol边界交互，后续可以替换传输。没有引入数据库，所有房间状态与请求结果保存在主机内存。

## 协议约定

- 帧：4字节长度 + 4字节协议版本 + 显式字段；最大262144字节。TCP分片在完整读到指定长度后才解析。
- 客户端消息：JOIN、READY、ACT、PING。
- 服务端消息：WELCOME、SNAPSHOT、ACK、PONG、ERROR。
- 加入需要房间号与口令；房主的0号座位由服务器预留；其他三位分配1～3号。
- JOIN 的 requestId 为本机保存的随机玩家身份，关闭或移动解压目录后仍稳定；昵称用于选择本机身份，不单独作为服务端认证凭据。
- 身份文件按昵称 SHA-256 命名，保存在用户 LocalAppData 的 identities 目录，文件锁防止多进程并发生成不同身份；不保存房间口令。
- 每个座位的192位连接恢复凭据仍仅在协议内部使用，不再让用户抄写或输入。创建者首次通过主机凭据加入后也绑定本机身份，不能靠公开的“host”标签抢房主席位。
- 开局前离线席位显示为空位；新人优先用空席，无空席时可复用离线客人席位。活动牌局保留四个原位，原身份自动恢复；同名、不同本机身份不能冒充玩家。
- 操作人由连接绑定的Session确定，网络消息没有允许玩家自报操作人字段。
- ACT携带requestId、round、context、action；每座位保留最近4096条操作的请求与结果。
- 相同请求ID和相同内容返回原结果，不重复执行；相同ID不同内容拒绝。
- round防止上一局的操作进入下一局；context代表回合或响应窗口。
- 同一响应窗口内，另一位玩家回应会增加revision，但不更换context；因此剩余候选玩家仍可按原窗口回应。裁决沿用规则优先级和座位距离，不按网络先后抢胡。
- 全量快照每次按具体玩家调用Game.view生成；不先广播完整Game再让客户端隐藏。
- 行牌期间不发送其他人手牌或暗杠内容；仅局末公开四家牌。未摸牌墙和其他人的恢复码始终不发送。

## 执行与资源边界

- 一个房间单线程有界队列处理所有变更。连接读写独立，不在Swing主线程阻塞读写。
- 每连接有界发送队列，慢连接溢出时断开并允许恢复；最多16条握手/重连连接。
- 每连接最多40条消息/秒，未加入连接超时关闭；客户端4秒心跳，连接无活动约15秒检测离线。
- 四人在线并准备后才创建游戏；结算后四人准备才开始下一局。
- 任一已入座玩家离线，活动牌局暂停；全部恢复后继续，没有自动代打或超时扣分。
- “本人托管”只在本人客户端运行原Bot，发送自己的合法动作；不是服务器补机器人。
- 主机服务生命周期由主机小窗口控制，关闭房主牌桌不关闭房间。

## 已知限制

- 一台主机一个房间，没有公共大厅、观战、踢人或换座。
- 无主机状态持久化，主机退出后需重新开房。客户端关闭后自动回原位的前提是主机仍运行，且使用原 Windows 用户的身份文件及相同昵称。
- 没有应用层TLS或公网证书流程，当前面向局域网和Tailscale私有网络；跨国线路与中继质量须由真实朋友实测。
- 没有完成早期work.md中的SQLite崩溃恢复、完整运维与长期跨国验收，不能将此次功能等同于全部规划完成。
- 规则数值与跟庄留白继续保留，房间创建后不允许某个客户端中途换规则或重新发牌。
