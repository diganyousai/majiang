# 四人联机使用与测试方法（2.2.2）

## 1. 使用哪个程序

使用 `QingzhuKouDianDianOnline.exe`，也附有 `play.cmd` 标准 Java 启动入口。给朋友发送完整的 `QingzhuKouDianDianOnline-2.2.2-Windows-x64.zip`，解压后保留 `app` 和 `runtime`；无需安装 Java。EXE 未签名，在启用了严格应用控制策略的设备上可能被拦截，详见 README.md。

四个人都使用同一份 2.2.2 发布包。程序保留单机练习及四人联机。

新增入口：单机练习、创建联机房间、加入联机房间。一个主机对应一个四座房间，没有公共大厅或账号系统。

## 2. 先在一台电脑上手动四开

1. 启动第一个 EXE，选“创建联机房间”。
2. 选择亲友房或金币规则与选项，确认。
3. 昵称填“房主”；监听地址用 `127.0.0.1`（仅本机）或默认 `0.0.0.0`；端口 `17890`；记下房间号和口令。
4. 出现“主机房间”小窗口，并自动打开房主牌桌。主机小窗口必须保持打开。
5. 再启动三次 EXE，每次选“加入联机房间”。
6. 三次都填主机 IP `127.0.0.1`、端口 `17890`、相同房间号/口令；昵称分别填“玩家1/2/3”。同一电脑的不同玩家必须使用不同昵称。
7. 切换四个牌桌，分别点击“准备”。只有四人全部准备才发牌，首局房主坐庄。
8. 每个窗口仅显示本人的手牌，并始终位于下方；按当前轮次手动出牌、报听、碰杠、胡或过。
9. 一局结束，四个客户端都看到相同结果和付款明细，牌桌亮出四家牌。点击“查看全场牌”核对四家手牌、弃牌和暗杠；四人分别点击“准备下一局”，由胡家坐庄，其他人的手牌重新隐藏。

可勾选四个客户端各自的“本人托管”，快速验证完整流程；这是每个客户端代操作自己的座位，服务端没有偷偷补入机器人。真人测试时取消托管。

**合格标准：** 三人准备不发牌；四人准备只开一局；四个不同座位与手牌；其他人的手牌为背面；同一出牌与分数四端一致；下一局等待四人准备。

## 3. 四台电脑在同一局域网测试

1. 主机电脑创建房间，监听保持 `0.0.0.0`，端口 `17890`。
2. 在主机窗口查看本机网卡地址，也可在主机 PowerShell 执行 `ipconfig`，找到实际联网网卡的 IPv4，例如 `192.168.1.100`。
3. 其他三台电脑加入，主机 IP 填实际的 `192.168.1.100`，其余房间信息相同。
4. 在主机 Windows 防火墙允许该联机 EXE 接收入站连接。不要关闭防火墙。
5. 四人准备，至少完成三局，并按第5节测试一次断线恢复。

`0.0.0.0` 是监听设置，不能作为朋友的加入地址。`127.0.0.1` 只表示正在操作的这台电脑，朋友不能用它连接你的电脑。

**合格标准：** 每台电脑都能连接，四人连续完成至少三局，无一方停留在旧牌桌或错误分数。

## 4. 不同国家：通过 Tailscale 测试

程序负责房间和牌局；Tailscale 提供设备之间的可达网络，游戏主机仍是你的电脑。

1. 四台电脑安装 Tailscale，各自登录，通过管理员邀请加入同一私有网络；不要把个人登录密码交给朋友。参考 [Tailscale 官方快速入门](https://tailscale.com/docs/how-to/quickstart)。
2. 确认朋友的设备可以访问主机；若网络配置了 ACL / Grants，允许朋友到主机的 TCP `17890`。
3. 只用 Tailscale 时建议直接监听自己的 Tailscale IPv4；`0.0.0.0` 会监听所有本地 IPv4 地址。主机窗口会列出网卡地址；也可通过 `tailscale ip -4` 查看。
4. 朋友的“主机IP”填主机的 Tailscale IPv4，常见形式为 `100.x.x.x`；端口、房间号、口令与主机相同。
5. Windows 防火墙要允许该来源到游戏端口。正常情况下不需要在家用路由器上做端口映射。
6. 四人进行至少60分钟实际对局，记录明显卡顿和中断；只通过本机自测，不能替代跨国网络验证。

Tailscale 可能直连，也可能经过中继，实际路线影响延迟，见 [官方连接机制](https://tailscale.com/docs/reference/connection-types)。当前协议为普通 TCP，没有额外应用层 TLS，建议跨国使用 Tailscale 的加密通道；未将直接公网暴露作为本版部署方式。

若默认防火墙提示未放行，可由主机在**管理员 PowerShell**按实际 EXE 路径创建限定来源的规则。下面示例路径为当前工作区交付位置：

```powershell
New-NetFirewallRule -DisplayName 'Qingzhu Mahjong Online TCP 17890' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 17890 -Program 'D:\majiang\QingzhuKouDianDianOnline\QingzhuKouDianDianOnline.exe' -Profile Any -RemoteAddress LocalSubnet,100.64.0.0/10
```

此命令只作为手工配置说明，程序不会自行修改防火墙；程序放到别处时必须修改 `-Program`。参数说明见 [Microsoft 官方文档](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule?view=windowsserver2025-ps)。

## 5. 断线、关闭牌桌与恢复

### 临时断网

- 客户端每4秒心跳，长时间无响应约15秒后触发重连；网线拔掉时不是必然立即检测到。
- 主机确认有人离线后整桌暂停，其他玩家不能继续出牌，也不会由服务端机器人代打。
- 保持客户端窗口打开，恢复网络后自动重连；也可点“重新连接”。
- 原座位、手牌、分数与未结束的响应窗口保持不变，四人重新在线后继续。

### 客户端关闭后再打开

1. 记住加入时使用的昵称，不需要抄写恢复码。
2. 关闭客户端牌桌。若是房主，仅关闭自己的牌桌，保留主机小窗口。
3. 在同一电脑、同一 Windows 用户下重开 EXE，选加入，填原主机、端口、房间号、口令及相同昵称。
4. 确认自动回到活动牌局原座位、手牌与分数；程序使用本机保存的随机身份验证，另一台电脑只填同名不能抢走座位。

房主也可直接在主机小窗口点“打开我的牌桌”。本机身份保存于 `%LOCALAPPDATA%/QingzhuMahjongOnline/identities/`，与解压目录无关，升级新版可以保留身份。同一电脑同昵称打开另一牌桌会替换旧连接。不要删除或向他人提供身份文件；它不包含房间口令。

**合格标准：** 离线后暂停；恢复后牌墙、手牌、分数与当前操作阶段不回退、不重复出牌；未结束的响应窗口继续等待原候选玩家。

### 主机关闭

本版牌局存于主机内存。关闭主机小窗口、主机进程退出或电脑重启，会结束房间；不能恢复旧牌局。主机重新建房后，玩家仍可用相同昵称正常加入新房间。

尚未开局时，离线席位显示为空位并允许新人入座，不再永久占位。原玩家回来时优先恢复仍保留的原席位；若该席位已给新人，则使用其它空位。对局开始后保留席位并暂停，原玩家自动恢复；不支持活动牌局中途替补。更换电脑、Windows 用户或昵称，以及删除身份文件，无法自动证明是原玩家。

### 听后锁牌检查

报听后，鼠标只能选择刚摸到的牌，点击原手牌不会换选；不能碰或再次报听。明杠、暗杠、补杠只有保持原听口不变时才允许，计分沿用普通杠规则。点击出牌只打刚摸到的牌；有合法胡牌时仍能胡牌。杠后补牌同样只能胡或打补到的牌；关闭后自动回位应保留“[听]”和原手牌。

## 6. 自动网络自测（无需朋友、无需安装 Java）

双击分发目录的 `test-network.cmd`。它通过随包运行时启动同一发布 JAR，在本机随机空闲端口启动隔离测试房间及四个真实 TCP 客户端，不占用正在玩的 `17890` 房间。

测试包括：口令与房间错误、协议版本/过大消息、分片消息、四人准备、第五人拒绝、身份与私牌隔离、重复请求、同请求号不同动作、断线暂停、本机身份自动回位、开局前离线席位复用、同名冒充拒绝、网络换听请求拒绝、听后合法杠及普通杠分、自动重连重试、多家响应与截胡、完整结算和下一局。

结果写入 `%LOCALAPPDATA%\QingzhuMahjongOnline\test-output`。只有 `network-report.json` 的 `status` 为 `passed` 且脚本显示成功，才算通过；失败时查看 `failure.txt`。

开发环境可运行：

```powershell
Set-Location 'D:\majiang\QingzhuMahjongSource'
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -TestOnly
```

该命令会运行原规则测试和新增网络测试。默认寻找工作区 `.tools` 中的 JDK 21；其他机器可传 `-JdkHome`。

## 7. 自动四窗口界面回归（会操作鼠标）

停止手动使用鼠标后执行：

```powershell
$taskApp = 'D:\majiang\QingzhuKouDianDianOnline\QingzhuKouDianDianOnline.exe'
Start-Process -FilePath $taskApp -ArgumentList '--network-smoke', 'D:\majiang\online-ui-test' -WindowStyle Hidden -Wait
```

它会打开四个真实客户端、准备开局、用鼠标出牌、关闭并恢复一个客户端、让各客户端托管完成一局，再准备下一局，最后自动关闭测试窗口。结果为 `online-smoke-report.json`，同时输出各座位、暂停及结算截图。测试约需1～3分钟，不能把跨国网络质量判断交给本机测试。

没有可用的原生鼠标交互环境时，可在发布目录用随包运行时执行事件派发版本：

```powershell
& '.\runtime\bin\java.exe' -Xmx512m -jar '.\app\qingzhu-mahjong.jar' --network-ui-test 'D:\majiang\online-ui-test'
```

该入口会创建真实 Swing 窗口和四条 TCP 连接，但使用 Swing 事件派发及按钮调用代替原生鼠标输入。报告明确记录输入方式；它不等同于实际鼠标操作验收。

## 8. 常见问题

| 现象 | 检查内容 |
| --- | --- |
| 连接被拒绝 | 主机窗口是否开着，IP/端口是否正确，是否误用旧单机 EXE |
| 连接超时 | 主机是否只监听127.0.0.1，防火墙、Tailscale访问策略和线路是否允许 |
| 房间满了 | 原玩家在原电脑使用相同昵称自动回位；活动牌局不允许他人替补，开局前离线席位可被新人使用 |
| 只有三人，不能开始 | 必须四人全部在线并准备 |
| 等待应牌不动 | 查看其余三家是否有人还未点碰/杠/胡/过；所有候选响应后统一裁决 |
| 房间暂停 | 有人断线，等待恢复；主机重启不能恢复此房间 |
| 协议不一致 | 四人使用同一份 2.2.2 ZIP |
| 端口已被占用 | 在开房时换为17891，并让朋友填写同样端口 |
| 结算后没自动开下一局 | 四人分别准备，不由某一人强制开局 |

亲友房具体牌型数值、跟庄及其他规则留白仍遵循此前确认，不因联机而改动。
